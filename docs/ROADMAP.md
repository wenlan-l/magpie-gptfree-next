# 路线图

每个阶段都必须能独立合并、独立回滚。验收标准写死，不做"感觉差不多"。

## P0 · 骨架与护栏（当前）

产出：仓库、`src/platform/`、诊断器、双平台 CI。

验收：
- [x] `npm run check` 与 `npm test` 在 `ubuntu-latest` / `windows-latest`、Node 20/22 全绿
- [x] 诊断包能在无依赖环境下跑完，且不读取任何凭据
- [x] 上游 v0.6.6 快照入库，作为行为对照

## P1 · 生命周期与侧边栏

产出：supervisor、`/healthz`、端口回退、入口页状态机、进程树回收。

验收：
- 侧车启动失败 / 端口被占 / 侧车被杀，三种情况下侧边栏都能显示可读原因并可重试，**不出现白板**
- 连续 50 次冷启动无一次卡在"连接中"
- Windows 上结束 Magpie 后无残留 `python.exe` / `node.exe`
- 单测覆盖状态机的每条边

## P2 · 存储、号池、导入

产出：单写者队列、原子 vault、导入流水线、额度统计。

验收：
- 25 个并发写入后文件始终可解析（已有测试）
- 导入 100 个账号过程中强制断电/杀进程，重启后不出现半写 vault
- Windows + OneDrive 目录下连续写入 200 次无 EBUSY 失败
- 上游的 14 项 Python 测试与 80 项 JS 测试在移植后仍全绿

## P3 · 协议适配器

产出：`ProtocolAdapter` 接口、上游 worker 装箱、fixture 契约测试。

验收：
- 上层代码不再 import 任何 `python/*`
- 协议替换只改 `src/protocol/` 与 fixtures，`core/` 与 `gui/` 零改动
- 契约测试能在无账号的情况下跑（用录制的响应）
- 一次真实账号的登录 + 一次文本 + 一次生图人工验证通过

## P4 · GUI 重写

产出：ES 模块化前端、路由、连接状态可见、错误可复制。

验收：
- 无构建步骤，无 npm 依赖
- 首屏在 300ms 内渲染出状态（不是空白）
- 所有失败路径都有可操作提示，不出现只有 spinner 的页面

## P5 · 巡检自动化

产出：上游 diff 巡检、协议金丝雀、告警。

验收：
- 上游有提交时产出候选清单：改了哪些文件、是否触碰协议、依赖变化
- 金丝雀每天一次，失败按错误码分类，连续两次失败才告警
- 任何自动合并都要求：diff 审查通过 + 测试全绿 + 人工确认

## 明确不做

- 不为了"跟上上游功能"直接抄别的仓库代码；只移植思路，重新实现并补测试。
- 不引入 npm 依赖（原生模块在 Windows 上是主要故障源）。
- 不在无账号验证的情况下宣称"生图可用"。
